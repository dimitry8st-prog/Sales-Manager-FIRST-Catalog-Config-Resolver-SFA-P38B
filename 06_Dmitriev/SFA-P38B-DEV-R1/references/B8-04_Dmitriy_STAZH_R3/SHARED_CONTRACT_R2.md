## Public wrapper ABI, common types
Each new package exports its module's api.py create_service(ports) -> service, service.execute(operation: str, request: dict) -> dict. execute is synchronous; it returns {"status": S, "data": D}, exact root keys only; S in OK,REPLAY,BLOCKED,CONFLICT,INVALID,UNAUTHENTICATED,UNAUTHORIZED,NOT_FOUND,STALE,DEPENDENCY_UNAVAILABLE,UNKNOWN. D is a JSON dict, operation-specific contract defines fields. No secrets/tokens in responses. Domain validation exceptions from existing functions map to INVALID with {"code": original_code}; existing APIs and exception classes themselves do not change. Unexpected DB/transport failures must not be relabelled OK; uncertain commit => UNKNOWN with stable identity, scoped reread, no new effects.
Strict scalar types: IDs trimmed nonempty str <=128 Unicode codepoints, no ASCII control/DEL/NUL; campaign_id is canonical lowercase UUID when mapped to runtime_campaign_id, not arbitrary display label; revisions nonnegative int excluding bool; SHA256 lowercase hex length64; timestamp ISO8601 timezone aware UTC-normalized; policy ints positive except F103 max_followups/cooldown >=0. Missing/unknown root request keys => INVALID {code:INVALID_REQUEST}; nested frozen F1 payloads use their original validators and exact schemas. Context/principal/clock/policy are supplied by trusted ports, never by request fields such as trusted=true, role, auth, owner_token.
CatalogScope (B8-01) and WorkerScope (B8-02) exact {client_id,campaign_id}; DatabaseScope (B8-08) exact {client_id,target_id}; LeadScope (B8-03..07) exact {client_id,campaign_id,lead_id,mailbox_ref,thread_id}. All fields nonempty IDs. No invented lead/mailbox/thread in prelead or DB tasks. F103 adapter maps campaign_id -> runtime_campaign_id and preserves other identity. All stored identities and effects include scope and immutable source/version/hash. A scope mismatch is never repaired by changing scope or silently dropping records.

Error precedence (before any effect): validate request shape/types -> UNAUTHENTICATED -> UNAUTHORIZED/cross-scope -> required dependency absent -> STOP/HUMAN gate for customer automation -> immutable replay equality/conflict -> expected revision/generation/expiry -> domain validation -> persistence/provider. A duplicate known successful operation returns REPLAY only after authentication/scope checks; STOP/HUMAN may return BLOCKED for automation even for duplicate proposals. Evidence-only record and incoming append are exempt from automated-send gate, never from auth/scope checks. Duplicate key + different canonical bytes => CONFLICT. Canonical JSON = UTF8 ensure_ascii=False, sort_keys=True, separators=(comma,colon), forbid NaN/Infinity; hashes over exact approved raw bytes when source contract uses byte hashes, do not replace by JSON hash.
