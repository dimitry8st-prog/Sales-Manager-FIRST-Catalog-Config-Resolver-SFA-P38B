1. ЧТО НУЖНО СДЕЛАТЬ

Создать небольшой Python-модуль, который получает словарь конфигурации одной кампании FIRST, проверяет его и возвращает отдельную нормализованную копию. Некорректный ввод отклоняется предсказуемой ошибкой. Модуль ничего не отправляет, не читает сеть, окружение, файлы или базу данных и не меняет исходный словарь.

FIRST работает с одним предложением и одним почтовым ящиком. Начальные языки пилота — английский и русский. Архитектура допускает дополнительные языки через конфигурацию и отдельно принятые языковые пакеты. Полной настройки продавца, запуска продаж или доказательства коммерческих фактов в этом задании нет.

Это структурная проверка доверенной серверной конфигурации. Даже успешно проверенный словарь не доказывает согласие владельца, владение ящиком, достоверность фактов или право отправки. Эти доказательства и разрешения проверяются последующим интегратором. Поле owner_approval_ref — ссылка на доказательство, а не сама авторизация. Нельзя брать эту конфигурацию прямо из письма клиента или результата модели.

now передаётся вызывающей стороной явно. Функция не получает текущее время сама. now должен быть datetime с часовым поясом и определённым utcoffset. Naive datetime запрещён. Поддерживаются временные зоны, корректно преобразуемые в UTC.

Никаких дополнительных публичных функций от других ещё не реализованных заданий не требуется. Внутренние вспомогательные функции допускаются.

4. СХЕМА ВХОДА

config — обычный dict со следующими обязательными полями и без неизвестных полей:

schema_version: ровно "FIRST_BINDING_INPUT_V1".
client_id: identifier.
runtime_campaign_id: канонический UUID в нижнем регистре, строка вида 11111111-1111-4111-8111-111111111111.
make_campaign_id: identifier. Это отдельный внешний идентификатор; не подменяет runtime_campaign_id.
offer: dict ровно с полями offer_id:identifier, name:text, description:text.
mailbox: dict ровно с полями mailbox_ref:identifier, sender_email:email.
owner_approval_ref: text.
binding_version: identifier.
valid_from: timezone-aware ISO8601 строка.
expires_at: timezone-aware ISO8601 строка.
release_mode: ровно "NO_OUTBOUND".
default_locale: locale_id.
allowed_locales: непустой list уникальных locale_id.
language_pack_versions: dict, ключи ровно совпадают с allowed_locales, каждое значение identifier.
daily_send_limit: целое число >=1, bool запрещён.
max_followups: целое число >=0, bool запрещён.
approved_facts: непустой list словарей; каждый словарь ровно с полями fact_id:identifier, text:text, source_ref:text; fact_id уникальны.

ОПРЕДЕЛЕНИЯ ТИПОВ:
- identifier: строка, удовлетворяющая ASCII regex [A-Za-z0-9][A-Za-z0-9_.:-]{0,127}; пробелы не допускаются. Использовать fullmatch.
- text: строка, после strip() не пустая. Возвращать её без изменения, включая исходные пробелы и Unicode; проверка пустоты не является нормализацией текста.
- locale_id: строка длиной 1..64, regex [A-Za-z][A-Za-z0-9]*(?:-[A-Za-z0-9]+)*; например en-GB, ru-RU, de-DE. Это локальный формат идентификатора, не реализация полного стандарта BCP47. Регистр сохранять; сравнение точное. Не ограничивать число языков двумя и не зашивать список разрешённых языков в Python enum.
- email: непустая строка; нормализовать strip().lower(); результат должен соответствовать regex [^\s@]+@[^\s@]+\.[^\s@]+. Это только синтаксическая проверка, не deliverability/владение. Не проверять DNS, SMTP или Hunter.
- ISO8601: разбирать datetime.fromisoformat после замены только конечного Z на +00:00; обязательны tzinfo и utcoffset. valid_from < expires_at и valid_from <= now < expires_at. Все сравнения по моменту времени, не по тексту.

default_locale обязан входить в allowed_locales. Нельзя добавлять недостающие версии языков, язык по умолчанию или факты автоматически. FIRST fixture включает en-GB и ru-RU; функция при этом остаётся универсальной для другого принятого набора языков. Полную бизнес-приёмку начальных EN/RU проводит интегратор отдельно.

6. ОШИБКИ

Всегда выдавать FirstBindingError с одним из кодов:
INVALID_INPUT — config не dict или now неверного типа/без timezone;
INVALID_SCHEMA — отсутствуют обязательные/есть неизвестные поля, schema_version не совпадает, вложенные offer/mailbox/fact имеют неверный набор полей;
INVALID_IDENTITY — неверный identifier или runtime UUID, включая binding_version и fact_id;
INVALID_OFFER — неверные name/description;
INVALID_EMAIL — неверный тип/пустой/некорректный sender_email;
INVALID_APPROVAL_REF — owner_approval_ref не text;
INVALID_VALIDITY — неверная дата, порядок дат, ещё не действующая или истёкшая конфигурация;
OUTBOUND_MODE_FORBIDDEN — release_mode не NO_OUTBOUND;
INVALID_LANGUAGE_CONFIG — неверный locale/default/list/duplicates/keyset/версия языкового пакета;
INVALID_LIMITS — неверные целочисленные лимиты;
INVALID_FACTS — список фактов пустой/не list, повтор fact_id, неверные text/source_ref.

При нескольких ошибках проверять группы в указанном порядке. INVALID_SCHEMA проверяет верхнюю схему сначала, вложенные схемы — при проверке соответствующей группы. Внутри одной группы порядок проверок на усмотрение автора, но он должен быть детерминированным. Для приёмки отдельные отрицательные fixtures содержат одну ошибку. Не допускать наружу случайный KeyError, TypeError, AttributeError или ValueError парсера для некорректного пользовательского входа. Не ловить BaseException и не скрывать ошибки программы общей успешной веткой.

8. ОБЯЗАТЕЛЬНЫЕ ТЕСТЫ

Использовать unittest. Проверить положительный пример, EN/RU и добавление synthetic de-DE с версией без изменения ядра; отсутствие/лишнее поле; UUID/внешний ID не смешиваются; bool вместо int; пустые и повреждённые вложенные структуры; timezone/UTC-смещения и обе границы периода; duplicate locale/fact; несовпадение keyset версий; Unicode; нормализацию email; независимость вложенных копий; вход остаётся неизменным; стабильные code без отражения секретного sentinel во всех ошибках. Повторный вызов с одинаковым now даёт равный результат. Модуль должен импортироваться без psycopg, credentials, сервера и сети.

11. КУДА ПОЙДЁТ КОМПОНЕНТ

Интегратор получит проверенный серверный binding. Его mailbox/scope используются при сборке binding для Annie normalize_inbound; это разные schema_version, поэтому адаптер преобразует их явно. allowed_locales/language_pack_versions и approved_fact_ids согласуются с результатом F1-06 и затем входят в server-owned policy для Camel. Здесь не импортировать ещё не принятые компоненты и не писать этот адаптер. Вклад — FG01; сама структурная проверка не закрывает FG01, не подтверждает реальную почту и не разрешает отправку. Существующий NO_OUTBOUND сохраняется.
