4. ОБЩИЕ ТИПЫ

identifier: строка regex [A-Za-z0-9][A-Za-z0-9_.:-]{0,127}, fullmatch.
locale_id: строка длиной1..64, regex [A-Za-z][A-Za-z0-9]*(?:-[A-Za-z0-9]+)*, fullmatch. Это локальный формат ID, не полный BCP47 parser. Сохранять регистр; сравнение точное. Не зашивать глобальный enum EN/RU или максимум числа языков.
text: строка не пустая после strip(); возвращать без изменения, с сохранением Unicode/пробелов.
approved_fact_ids: list уникальных identifier; может быть пустым для пакетов без фактических утверждений. Это серверный список разрешённых ссылок, не доказательство истинности фактов. Неверный тип/дубликаты — ошибка.

5. СХЕМА ПАКЕТА

pack — dict ровно с полями:
schema_version: "FIRST_LANGUAGE_PACK_V1";
locale: locale_id;
version: identifier;
templates: непустой dict с ключами template_id:identifier.

Значение каждого templates[template_id] — dict ровно с полями:
kind: одно из INITIAL, QUESTION, OBJECTION, FOLLOWUP, HANDOFF;
locale: locale_id, ровно pack.locale;
subject: строка, для INITIAL непустая после strip(), для остальных может быть пустой;
body: text;
fact_ids: list уникальных identifier, каждый входит в approved_fact_ids.

Никаких неизвестных полей. Никакой интерполяции {переменных}, выполнения выражений или HTML-рендеринга: subject/body хранятся как непрозрачный текст. Подстрока, похожая на команду, не выполняется. fact_ids пустой допустим; это не автоматическая гарантия, что текст фактически ничего не утверждает. Проверку смысла и качества перевода делает независимый QA позднее.

validate_language_pack возвращает глубокую копию pack с теми же schema_version и значениями. Никаких verified=true/approved=true/grant полей не добавлять.

6. СХЕМА РЕЕСТРА И ЗАГРУЖЕННОГО РЕЗУЛЬТАТА

registry — dict ровно с полями:
schema_version: "FIRST_LANGUAGE_REGISTRY_V1";
registry_version: identifier;
default_locale: locale_id;
active_locales: непустой list уникальных locale_id;
language_pack_versions: dict, ключи ровно active_locales, значения identifier.

default_locale входит в active_locales. packs — list пакетов; для каждого active_locale ровно один пакет, его locale и version точно совпадают с реестром. Повтор локали, недостающий пакет, лишний неактивный пакет или неверная версия отклоняются. Предварительно validate_language_pack проверяет каждый пакет с тем же approved_fact_ids. Разные языки могут использовать один и тот же template_id: это не конфликт, потому что выбор языка предшествует выбору template.

load_language_registry возвращает dict ровно:
schema_version: "FIRST_LANGUAGE_REGISTRY_LOADED_V1";
registry_version: копия registry.registry_version;
default_locale: копия registry.default_locale;
active_locales: копия registry.active_locales в исходном порядке;
language_pack_versions: глубокая копия mapping;
approved_fact_ids: копия входного списка;
packs_by_locale: dict locale -> проверенная глубокая копия соответствующего pack.

Не считывать дополнительные пакеты автоматически и не делать fallback на случайный язык. Наличие версии в JSON не доказывает независимую приёмку пакета; серверный вызывающий код обязан передавать только принятые версии. Реальные EN/RU входят в более позднюю приёмку FIRST, здесь только synthetic corpus.

7. ПОЛЯ ДЛЯ CAMEL

build_policy_language_fields заново валидирует структуру loaded: точная схема/ключи из раздела6, корректный approved_fact_ids; соответствие active_locales/default/version и каждого packs_by_locale проверяется по правилам разделов5–6. Это защищает от случайной мутации объекта между вызовами; функция не доверяет произвольному dict только из-за schema_version.

locale обязан быть активным. Функция не определяет язык по тексту. Возвращает ровно:
  locale: выбранный locale;
  allowed_locales: копия loaded.active_locales;
  language_pack_versions: копия loaded.language_pack_versions;
  approved_templates: dict только шаблонов выбранного языка, каждый элемент:
    {"body": исходный body, "fact_ids": копия fact_ids, "locale": выбранный locale}.

Все template_id выбранного пакета сохраняются. kind/subject остаются в loaded.packs_by_locale, но не передаются в минимальные шаблоны Camel. Camel не выбирает template по kind самостоятельно: доверенный classifier/adapter позже выбирает подходящий template_id и проверяет соответствие события. Это не выполняется здесь. Сама проекция не разрешает отправку INITIAL/HANDOFF через reducer. Нельзя молча добавлять product_id/sender_ref/policy_version/лимиты — их предоставит интегратор из server-owned binding, отдельно сверив версии. Полного FIRST_POLICY_V1 здесь не возвращать.

8. КОДЫ ОШИБОК

INVALID_INPUT — аргумент не того базового типа;
INVALID_FACT_SET — неверный approved_fact_ids;
INVALID_SCHEMA — неверный schema_version или набор полей;
INVALID_IDENTIFIER — неверный registry_version/version/template_id;
INVALID_LOCALE — неверный формат локали, duplicate active_locales или default отсутствует в active_locales;
INVALID_TEMPLATE — неверный kind/body/subject/fact_ids structure, повтор fact_id;
TEMPLATE_LOCALE_MISMATCH — template.locale отличается от pack.locale;
UNAPPROVED_FACT — структурно корректный fact_id отсутствует в approved_fact_ids;
PACK_SET_MISMATCH — missing/extra/duplicate локаль пакета или неверный keyset language_pack_versions/packs_by_locale;
PACK_VERSION_MISMATCH — версия пакета отличается от реестра;
LOCALE_NOT_ACTIVE — корректный locale запроса build_policy_language_fields отсутствует в активном наборе.

Все ошибки — LanguageRegistryError; str(error) содержит только code. Не выводить тексты шаблонов или входные данные. Порядок групп проверки: базовые типы -> approved_fact_ids -> схема контейнера -> идентификаторы/локали -> состав/версии пакетов -> содержимое шаблонов. validate_language_pack проверяет базовые типы/approved_fact_ids/схему/идентификаторы/локали/шаблоны. При нескольких ошибках достаточно детерминированного порядка, задокументированного автором. Приёмочные negative fixtures изолируют одну ошибку. Наружу не должны выходить случайные KeyError/AttributeError/TypeError от повреждённых входных данных.

Отдельные отрицательные примеры на глубоких копиях:
- packs[1]["version"] = "ru-v2" -> PACK_VERSION_MISMATCH.
- packs[1]["templates"]["explain"]["locale"] = "en-GB" -> TEMPLATE_LOCALE_MISMATCH.
- packs[1]["templates"]["explain"]["fact_ids"] = ["not-approved"] -> UNAPPROVED_FACT.
- packs.pop() -> PACK_SET_MISMATCH.
- registry["active_locales"].append("ru-RU") -> INVALID_LOCALE.
- build_policy_language_fields(валидный loaded, locale="de-DE") -> LOCALE_NOT_ACTIVE.
- packs[0]["templates"]["explain"]["body"] = "  " -> INVALID_TEMPLATE.

Расширение: добавить de-DE в active_locales, de-DE:"de-v1" в mapping и synthetic пакетde-DE версииde-v1. Код модуля не менять. Этот тест доказывает расширяемость, но не поддержку реального немецкого рынка/языка.
