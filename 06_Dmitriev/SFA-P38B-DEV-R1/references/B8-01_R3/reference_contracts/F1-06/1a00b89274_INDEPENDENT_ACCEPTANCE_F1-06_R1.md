## Блокирующие находки

### IA-01 — нет проверки `fact_ids` на список

Требования: §5 — `fact_ids` является list уникальных identifier; §7 — повторная проверка loaded; §8 — неверная структура `fact_ids` даёт `LanguageRegistryError("INVALID_TEMPLATE")`, случайный `TypeError` запрещён.

В модуле строки **174–185** сразу перебирают `template["fact_ids"]`, не проверяя `isinstance(..., list)`.

- `fact_ids=""`, `fact_ids={}`, `fact_ids={"fact-test":"ignored value"}` принимаются. При разрешённых ссылках `a` и `b` принимается также строка `"ab"`.
- `fact_ids=None`, `42` или `False` выбрасывают обычный `TypeError` (`object is not iterable`).
- Все варианты подтверждены отдельно через `validate_language_pack`, `load_language_registry` и `build_policy_language_fields`: **21 проваленный случай**.
- В результате Camel-проекция может содержать строку или dict вместо требуемого списка ссылок.

Нужная доработка: явная проверка list до любого перечисления, затем существующие проверки идентификаторов/дубликатов/разрешений. Добавить negative tests для JSON scalar/object типов через все публичные функции, включая мутацию ранее корректного loaded.

### IA-02 — неверный `kind` выбрасывает случайный `TypeError`

Требования: §§5, 8 — только пять допустимых kind; неверный kind отклоняется контролируемой ошибкой `INVALID_TEMPLATE`.

В модуле строка **157** проверяет членство в `frozenset` без проверки типа. `kind=[]` и `kind={}` дают `TypeError: unhashable type: 'list'/'dict'`. Это обычные JSON-совместимые повреждённые входы, не специальные Python-объекты. Подтверждено через все три публичные функции: **6 проваленных случаев**.

Нужная доработка: проверка строкового типа до membership и тесты нестроковых JSON значений. Оборачивать весь модуль в общий catch вместо проверки структуры не требуется.

### IA-03 — `build` не связывает ключ `packs_by_locale` с `pack.locale`

Требования: §§6–7 — каждый активный язык имеет ровно один соответствующий пакет, а `build_policy_language_fields` заново проверяет соответствие структуры и отдаёт только шаблоны выбранного языка.

В модуле строки **334–337** проверяют пакет сам по себе и его версию, но не проверяют `pack["locale"] == active_locale`. Строки **344–350** выбирают пакет по ключу dict и проставляют в результат запрошенную locale.

Воспроизведения:

1. В ранее корректном loaded под ключом `en-GB` поменять внутреннюю локаль пакета и его шаблона на неактивную `de-DE`: `build(..., locale="en-GB")` принимает объект.
2. В том же месте поставить `ru-RU`: принимаются две внутренние локали `ru-RU`, несмотря на отсутствие внутреннего пакета `en-GB`.
3. Создать корректные EN/RU пакеты с одинаковым разрешённым identifier версии `v1`, затем переставить два значения `packs_by_locale`. Запрос `en-GB` возвращает **русский body**, но маркирует его `locale="en-GB"`.

Все **3 случая** должны быть отвергнуты как `PACK_SET_MISMATCH`; фактически приняты. Это нарушает требование защиты от мутации и изоляцию языковых шаблонов.

Нужная доработка: проверять соответствие внутреннего locale ключу и целостность внутреннего набора локалей при повторной валидации; покрыть inactive/duplicate/swapped случаи, включая одинаковые версии разных локалей. Не вводить запрет общих version identifiers — такого ограничения в ТЗ нет.
